<objective>
Ship migration 0025: the foundational DB state-machine changes for verification-aware results.
Adds a tri-state `status` enum on `tournaments.completions` (D-08) so "queue drained" is detectable,
extends the `tournaments.editions` status CHECK with `awaiting_results` plus a `start_announced` marker (D-06),
and rewrites `process_edition_transitions()` to be TIMING-ONLY — it no longer snapshots the leaderboard,
writes the `edition_rollover` outbox row, or drives reward grants (D-06). Also lands the Wave 0 schema
test scaffolds so downstream waves have automated verification targets.

Purpose: Without the tri-state, reject leaves `verified=FALSE` (indistinguishable from pending) so the
poller can never detect drain. Without the cron rewrite, results are still snapshotted at the grid
boundary and pending runs are permanently excluded. This plan is the bedrock both halves stand on.
Output: 0025 migration + extended schema integration test.
</objective>
