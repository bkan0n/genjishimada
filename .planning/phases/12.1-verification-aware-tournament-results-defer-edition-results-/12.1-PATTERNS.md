### `apps/api/services/tournament_outbox_service.py` (MODIFIED — poller gains drain + results computation)

**Analog:** itself. Extend the publish-before-mark loop `publish_pending_transitions` (lines 108-192) and the module docstring invariant (21-38, MUST be preserved).

**The transactional loop to extend (lines 152-192):**
```python
async with pool.acquire() as conn, conn.transaction():
    rows = await repository.fetch_unpublished_transitions(conn=conn)
    for row in rows:
        routing_key, event = _build_event(row)
        edition_id = event.edition_id
        for entry in event.results:
            pending_xp_events += await reward_service.award_cycle_end(entry, conn=conn)
            await _reset_non_participant_streaks(repository, entry, conn=conn)
        await service.publish_message(
            routing_key=routing_key, data=event, headers=Headers({}),
            idempotency_key=f"tournament:rollover:{edition_id}",
        )
        await repository.mark_transition_published(row["id"], conn=conn)
# Transaction committed: publish deferred, non-idempotent XP notifications.
await reward_service.publish_xp_events(pending_xp_events)
```
**Reuse verbatim (RESEARCH Don't-Hand-Roll):** the `for entry in event.results: award_cycle_end(...) + _reset_non_participant_streaks(...)` grant loop (168-171) — the new drain branch must build a `TournamentCycleCompletedEvent` per child cycle from a fresh `fetch_leaderboard` call and feed it into this SAME loop. Keep grants INSIDE the transaction (docstring 21-38 is an explicit invariant — moving them out is an anti-pattern).

**Routing-table extension (line 68):** add the new event to `_EVENT_ROUTING`:
```python
_EVENT_ROUTING: dict[str, tuple[str, type[msgspec.Struct]]] = {
    "edition_rollover": ("api.tournament.rollover", TournamentRolloverEvent),
    # NEW: "edition_results": ("api.tournament.results", TournamentEditionResultsEvent),
}
```
**Idempotency-key pattern (line 180):** the new results publish uses `idempotency_key=f"tournament:results:{edition_id}"` (mirrors `tournament:rollover:{edition_id}`).

**RECOMMENDED structure (RESEARCH Pattern 2 + Pitfall 3):** add `process_awaiting_results_editions(conn)` called inside the same `async with pool.acquire()...transaction()` block; on drain, write an `edition_results` outbox row (reusing `create_pending_transition` at repo:1662) so the existing publish-before-mark machinery drains it next tick — DO NOT direct-publish (loses at-least-once).

**Poller lifespan (`apps/api/app.py:72-105`) — NO change needed**; it already drives `publish_pending_transitions` every ~10s. The defensive `db_pool is None` guard (133-139) and the broad-except loop already cover the new work.

### `apps/api/services/tournament_service.py` (MODIFIED — verify/reject write the tri-state)

**Analog:** itself. The tri-state write happens in `_set_verified` (802-883), called by `verify_tournament_completion` (728-766) and `reject_tournament_completion` (768-800).

**Current terminal/no-op guards to rewrite (RESEARCH Pitfall 4) — lines 842-857:**
```python
# Terminal guard (CR-01): a verified run cannot be rejected back to unverified...
if not verified and existing["verified"]:
    raise AlreadyVerifiedError(tournament_completion_id)
...
if verified and existing["verified"]:
    return await self._noop_verdict_job(...)
```
These read `existing["verified"]`. After the migration `verified` is a generated column; rewrite the reads to `existing["status"]` (`== 'verified'`), and the writes (via the repo, below) target `status` not `verified`. The `_set_verified(..., verified: bool, ...)` signature can stay bool-driven (verify=True→'verified', reject=False→'rejected') OR migrate to a `target: Literal['verified','rejected']` — planner's choice; the bool path is the smaller diff.

**Atomic-conn pattern to preserve (lines 861-882):** the inner `_do(active_conn)` closure + `if conn is None: async with self._pool.acquire() as raw_conn, raw_conn.transaction():` wrapper keeps the row flip + participation-XP grant atomic. Force-publish service method (D-03) should reuse this same acquire-or-inject pattern.

**New service method `force_publish_results` (RESEARCH Pattern 8):** model the error path on `bootstrap_edition`'s `CycleAlreadyLiveError → 409` (route 511-517); raise a domain error when no `awaiting_results` edition exists. It runs the poller's drain branch ignoring `pending` rows.
