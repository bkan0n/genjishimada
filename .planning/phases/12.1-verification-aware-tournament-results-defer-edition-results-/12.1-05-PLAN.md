<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Discord user (slash command) → bot is_mod gate → API force-publish route | the only client-facing trigger for abandoning pending runs; the bot's single API key cannot distinguish callers, so the bot-side role check is the authoritative gate |
| RabbitMQ (api.tournament.results) → bot consumer | a re-delivered results event must not double-transfer the champion role or double-post |
| event payload (winner ids, names) → Discord mention | free-text names in announcements are an injection vector |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12.1-14 | EoP | /tournament publish-results | mitigate | Authoritative bot-side is_mod (mod or sensei) gate before any API call (matches /tournament-reroll); `default_permissions(manage_guild=True)` is a UI hint only. Test asserts a non-mod caller never reaches the API. |
| T-12.1-15 | Spoofing/Tampering | results announcement mentions | mitigate | Winners referenced ONLY by numeric `<@id>` inside a ui.TextDisplay with an `AllowedMentions(users=allow-list, everyone=False, roles=False)` — no free-text name in a mention (reused verbatim from existing rollover card). |
| T-12.1-16 | Tampering (double-transfer) | _on_edition_results re-delivery | mitigate | `@queue_consumer(idempotent=True)` claims the message id; combined with the publisher-side `tournament:results:{edition_id}` key, a re-delivered results event cannot double-transfer the champion role or double-post. |
| T-12.1-17 | Tampering (premature transfer) | results_pending placeholder path | mitigate | When results_pending=True the rollover event carries empty results, so the transfer loop is skipped and the previous champion keeps the role (D-05) — no premature/role-less transfer. Test asserts no transfer on the pending path. |
| T-12.1-SC | Tampering | npm/pip/cargo installs | accept | No package installs (RESEARCH: nothing to install). |
</threat_model>
