`pending` (the original D-08 bug) and the poller can never see the queue drain. Until a working
`count_inflight_verifications` exists, the poller has nothing to count.

| service → database (status write) | the write must target the writable `status` column, never the generated `verified` column |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-12.1-05 | Tampering | reject path writing wrong column | mitigate | reject now writes `status='rejected'` (not `verified=FALSE`); test asserts the DB row's status post-reject — closing the D-08 indistinguishability bug that would let the poller mis-detect drain and mis-rank/mis-reward. |
