# Phase 12.1 Plan 01: Verification-aware tournament results (DB bedrock) Summary

**Migration 0025 lands the tri-state `tournaments.completions.status` (pending/verified/rejected) with a STORED generated `verified` mirror, adds the `awaiting_results` edition status + `start_announced` marker, and rewrites `process_edition_transitions()` to be timing-only (no snapshot, no outbox row) — the foundational DB state-machine both halves of Phase 12.1 stand on.**

## Accomplishments
- Tri-state `status` column on `tournaments.completions` with a `CHECK (status IN ('pending','verified','rejected'))` — makes "verification queue drained" detectable (`COUNT(*) WHERE status='pending'`) and the illegal "verified AND rejected" state unrepresentable (D-08, T-12.1-01).
- `verified` re-added as a STORED generated column (`GENERATED ALWAYS AS (status = 'verified') STORED`) — every existing `verified DESC` ranking read and SDK `verified` field keeps working unchanged; only writes move to `status`. Ranking preserved (verified runs sort above pending/rejected regardless of time).
- `tournaments.editions` status CHECK extended with `awaiting_results`; new `start_announced boolean NOT NULL DEFAULT FALSE` marker (D-06).
- `process_edition_transitions()` rewritten timing-only: flips the due edition `active -> awaiting_results`, child cycles `active/finalizing -> finalizing`, creates edition N+1 grid-anchored (`started_at = prev.ends_at`, never `now()`), and writes NO outbox row and NO leaderboard snapshot (D-06, T-12.1-03).
- 7 Wave 0 schema test scaffolds added as automated verification targets for downstream waves.

## Decisions Made
- **Tri-state representation:** TEXT + CHECK with a STORED generated `verified` mirror (RESEARCH Pattern 5, Option 1). Chosen over dropping `verified`/rewriting the CTEs because it preserves the entire ranking surface, all SDK `verified` fields, and the frontend contract with zero ranking-code churn while making `status` the write-side source of truth.
- **Backfill rule:** `verified=FALSE -> 'pending'` (conservative — a historical FALSE row was never an explicit rejection).
- **Scope:** kept strictly to the migration + schema test file. The verify/reject write-path rewrite (`set_tournament_verified`) and poller-owned results computation are owned by downstream plans 12.1-03/04.
