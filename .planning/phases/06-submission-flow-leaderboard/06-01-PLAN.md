## Trust Boundaries

| Boundary | Description |

| API -> DB | Service-layer validation before SQL execution; asyncpg positional params prevent injection |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Spoofing | submit_completion user_id | accept | Bot-only endpoint via API key + tournaments:write scope (D-06). Bot passes authenticated Discord user's ID. No additional validation needed at service layer. |
| T-06-02 | Tampering | SQL injection via cycle_id, user_id | mitigate | asyncpg positional parameters ($1, $2) used exclusively in all repository methods -- no string interpolation |
| T-06-03 | Tampering | Race condition: speed check TOCTOU | mitigate | Single transaction with connection-level isolation per D-02. CTE cross-write is atomic single-statement. core.completions trigger is safety net. |
| T-06-04 | Repudiation | Tournament completion submitted | accept | Completion records persisted with inserted_at timestamp and user_id. No additional audit logging required for v1. |
| T-06-05 | Information Disclosure | Leaderboard data | accept | Leaderboard data is intentionally public within the community. User display names are already public in Discord. |
| T-06-06 | Denial of Service | Rapid submission spam | accept | Per-cycle UNIQUE constraint + speed enforcement naturally rate-limits (only faster times accepted). Scope guard restricts to bot API key. |
| T-06-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this phase. All dependencies already present. |
</threat_model>
