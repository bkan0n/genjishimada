<objective>
Wire tournament auto-detection into the shared completion submit path and propagate verification to the linked tournament row. This is the highest-risk change in the phase (it edits the normal-completion hot path), so it carries the D-07 regression guard and the precise CheckViolationError catch.

Three behaviors land here:
1. D-01 auto-detect + D-04 PB path: a normal completion on the active cycle's map inserts a tournament row and links it via `core.completions.tournament_completion_id` in the same transaction.
2. D-07 relax + D-03: on an active tournament map, a valid slower-than-PB run (rejected by the 0017 speed trigger as `CheckViolationError`) is caught and recorded as a tournament row with NO core row; non-tournament maps keep the existing HTTP 400.
3. D-04a verify propagation: inside `verify_completion`, when the verified core row links a tournament row on an active cycle, flip the tournament row verified + award participation XP + publish `TournamentVerificationChangedEvent`.

Purpose: Tournament times now flow through the same verification pipeline as completions; the leaderboard fills via auto-detection.
Output: Modified submit/verify service logic + FK link + regression tests.
</objective>
