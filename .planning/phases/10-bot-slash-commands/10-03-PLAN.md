<objective>
Deliver the four Discord slash commands (the visible feature of this phase and ADM-03):
`/tournament info`, `/tournament leaderboard`, `/tournament streak` (player group, D-05) and the
separate flat `/tournament-reroll` admin command (D-06). All live in
`apps/bot/extensions/tournaments.py` alongside the Phase-9 `TournamentHandler`, reusing its embed
styling (D-11) and the custom paginator (D-13). The authoritative admin access control is the
BOT-SIDE Mod/Sensei role check (D-07) — `default_member_permissions` is a UI hint only.

Purpose: complete the four ROADMAP success criteria + ADM-03. Depends on the streak endpoint
(Plan 10-01) and the wrappers + CategoryTransformer (Plan 10-02). Resolved open questions:
OQ1 — `/info` computes `ends_at = active.started_at + (weekly→7d / biweekly→14d)` locally from the
category's `cycle_frequency` (no API change); OQ2 — leaderboard rows render `<@user_id>` mentions.
Output: extended `tournaments.py` and a bot-side unit test file.

404 → zero-state ownership (D-04): Plan 10-01's streak endpoint deliberately 404s when no streak
row exists; the BOT owns the "no record → zero" mapping (per the Architectural Responsibility Map).
The bot's `APIService._request` raises `utilities.errors.APIHTTPError` (carrying `.status`) on any
non-2xx, so `/tournament streak` wraps `api.get_tournament_streak(...)` in
`except APIHTTPError as e:` and, when `e.status == HTTPStatus.NOT_FOUND`, renders current 0 / max 0
with the encouraging copy instead of surfacing an error.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Discord user → slash command | Untrusted invoker; admin audience must be restricted bot-side |
| bot → API (single full-scope X-API-KEY) | API scope does NOT distinguish Discord callers — the bot key passes all scopes |
| user-supplied names/codes → embed rendering | Free-text could carry mention/ping injection |
