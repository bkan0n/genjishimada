<objective>
Add the one missing piece of backing infrastructure for `/tournament streak` (D-01): a
player-readable `GET /api/v3/tournaments/streaks/{user_id}` route plus the matching
`TournamentService.get_streak` method. The repository method (`fetch_streak`) and the SDK
struct (`TournamentStreakResponse`) already exist from Phase 8 — only a new domain exception
(`StreakNotFoundError`), the service method, the route handler, and tests are missing.

Purpose: the bot's `/tournament streak` command (Plan 10-03) reads this endpoint. Per D-04 the
"no streak record → zero" presentation is handled BOT-SIDE, so this endpoint stays a pure data
read that 404s when absent. This plan is the runtime dependency for the bot streak wrapper.

Layering decision (resolves the CLAUDE.md three-tier deviation): the CLOSEST live analog,
`get_category` (service `tournament_service.py:140-155`, route `routes/v3/tournaments.py:165-188`),
follows the project hierarchy exactly — the SERVICE raises a domain exception
(`CategoryNotFoundError`) and the ROUTE catches it and converts to a `CustomHTTPException(404)`.
This plan MIRRORS that: `get_streak` raises a new `StreakNotFoundError(TournamentsError)` when no
row exists (NOT returning `None`), and the route catches it → 404. This keeps the new endpoint
consistent with the live `get_category` pattern rather than introducing a one-off `None`-return.
Output: a `StreakNotFoundError` domain exception, a scoped read endpoint + service method
mirroring `get_category`, and integration + service tests proving 200 / 404 / scope behavior.
</objective>
