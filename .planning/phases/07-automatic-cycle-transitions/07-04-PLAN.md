<objective>
Fix the cold-start lifespan ordering race in the tournament outbox poller. On a fresh API start, `tournament_outbox_poller._loop` runs its first `publish_pending_transitions(_app.state)` BEFORE the `litestar-asyncpg` plugin's lifespan has populated `state.db_pool`, causing `KeyError: 'db_pool'` → `AttributeError`, logged as `[!] tournament outbox poll failed`. The poller self-heals on the next ~10s tick, so the impact is cosmetic log-noise + up to ~10s of first-poll delay.

Purpose: Eliminate the startup error and remove the dependence on the broad `except` self-heal for normal cold starts, without changing any delivery semantics.
Output: A defer-first poll loop, a defensive readiness guard in the service, and a regression test that asserts the no-op behavior without a live broker.
</objective>

Edit A — apps/api/app.py, the `_loop` inside `tournament_outbox_poller` (~lines 82-94):
- Move the existing `await asyncio.sleep(10)` from the BOTTOM of the `while True:` body to the TOP, so the very first poll is deferred ~10s — long enough for the asyncpg lifespan (entered AFTER the poller's lifespan) to populate `state.db_pool` during startup. The cadence stays exactly ~10s (D-12): poll happens once per loop after each sleep. Keep the `try/except asyncio.CancelledError: raise / except Exception: log.exception("[!] tournament outbox poll failed")` block exactly as-is — it still survives transient errors, and the `await asyncio.sleep(10)` at the top of the body is the cancellation point the lifespan `finally` (D-08) relies on.
- Update the inline comment / docstring note so it documents WHY the sleep is first: "Sleep precedes the first poll so the asyncpg lifespan (entered after this poller's lifespan) has populated state.db_pool before the first publish — avoids the cold-start db_pool race." Keep the existing docstring's D-12/D-08/D-10 references.

Edit B — apps/api/services/tournament_outbox_service.py, `publish_pending_transitions` (~line 97):
- Replace the direct `pool: Pool = state.db_pool` with a defensive readiness guard using the dict-like State API: read `pool = state.get("db_pool")` and if it is `None`, `log.debug("[!] outbox poll skipped: db_pool not ready")` and `return` early (clean no-op, no exception). Only proceed to build the service/repositories and acquire a connection when `pool` is not None. After the guard, narrow the type (e.g. `pool` is now a `Pool`) so BasedPyright strict stays happy — assign to a `Pool`-typed local or keep using the guarded variable; `state.get` returns `Any` from State so an explicit annotation `pool: Pool | None = state.get("db_pool")` then early-return keeps the rest typed.
- This guard is belt-and-suspenders: Edit A removes the race in practice; Edit B guarantees the function can never raise on a missing pool even if entered early. Use `%s`-style logging, no f-strings.

Reference: gap diagnosis in 07-UAT.md (Test 1) and 07-02-SUMMARY.md (poller cadence D-12, cancellation D-08). Root cause = lifespan ordering race, not a wrong state key.
