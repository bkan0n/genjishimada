<objective>
Close the single major UAT defect from 09-UAT.md (Test 1): the bot's periodic DLQ sweep throws `ChannelNotFoundEntity: NOT_FOUND - no queue 'api.tournament.cycle_completed.dlq'` every interval and cascades into `Channel closed by RPC timeout` for the next queues in the same sweep.

Purpose: Two coordinated fixes for one root cause.
- Part A (declaration, primary): The Phase-9 tournament queues and their `.dlq` companions were never added to `infra/rabbitmq/definitions.json`. Every other queue declares both its main queue and `.dlq` there with matching `x-dead-letter-*` args; the tournament queues are missing (grep `tournament` in definitions.json = 0). Add the four entries, mirroring the `api.xp.grant` + `api.xp.grant.dlq` pair exactly. This is the canonical, broker-load-time, idempotent fix that matches every other queue.
- Part B (resilience, secondary): `_process_all_dlqs_once` acquires ONE pooled channel and reuses it across every base queue in the loop, so a single channel-level exception (the NOT_FOUND) closes that shared channel and the remaining queues fail with `Channel closed by RPC timeout`. Harden the sweep so one missing/failing DLQ cannot poison the rest.

Output: the four new declarations in `definitions.json`, a hardened DLQ sweep in `apps/bot/extensions/rabbit.py`, and a unit test in `apps/api/tests/bot/test_rabbit_dlq_sweep.py` proving the isolation. Re-running `/gsd:verify-work 9` Tests 1-6 is then unblocked.
</objective>

DLQ sweep internals to harden (apps/bot/extensions/rabbit.py):
- `_process_all_dlqs_once` (263-278): `async with self._channel_pool.acquire() as channel:` ONE channel, then `for base_queue in self._queues: try: self._process_one_dlq(channel, base_queue) except Exception: log.exception(...)`. The try/except already catches the exception, BUT the channel is already CLOSED by the broker after a channel-level error, so every subsequent `_process_one_dlq` on the same channel fails with ChannelInvalidStateError. The except cannot un-close the channel.
- `_process_one_dlq` (280-342): `dlq = await channel.declare_queue(dlq_name, passive=True)` (line 291) is what raises ChannelNotFoundEntity when the .dlq is absent; a passive declare failure is a channel-level error that closes the channel.
- `_get_channel` (118-124): `async with self._connection_pool.acquire() as connection: return await connection.channel()` — acquiring a fresh channel per base queue is cheap (connection pool max 2, channels are lightweight).
- `self._channel_pool` is `Pool(self._get_channel, max_size=10)`; `self._queues` is a dict keyed by base-queue name.

Existing bot-test path-load + stub pattern to reuse (apps/api/tests/bot/test_tournaments_handler.py:40-119): path-load the bot module under test with `importlib.util.spec_from_file_location`, snapshot/evict `utilities`+`extensions` from sys.modules while `apps/bot` is on sys.path, restore in `finally`. `_install_queue_registry_stub()` registers a minimal `extensions`/`extensions._queue_registry` shell.
