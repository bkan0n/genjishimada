<objective>
Build the `TournamentHandler` bot extension: two cycle-scoped-idempotent queue consumers that post the new-cycle and results announcement embeds and transfer the per-category Discord champion role, plus the public `bot.tournaments` wiring on `core.Genji`.

Purpose: This is the phase deliverable — DSC-01 (new-cycle announcement), DSC-02 (results announcement), DSC-03 + RWD-03 (champion role transfer folded into the results embed). The bot is consumer-only: it sources missing embed data (category name + champion_role_id, map difficulty + banner) via the API on event receipt (D-07), never reads Postgres. The single most important wiring detail: the handler MUST be attached as a PUBLIC `bot.tournaments` attribute, or `RabbitHandler._collect_queue_handlers` (which skips `_`-prefixed attrs) silently never registers the consumers (#1 pitfall — queues fill then DLQ).

Output: `apps/bot/extensions/tournaments.py` (TournamentHandler + two consumers + setup), the public `tournaments` property on `core.Genji`, and the filled-in handler unit tests (Plan 09-01 stubs become green).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| RabbitMQ → bot consumer | Untrusted-shaped event payloads cross here; decoded into typed msgspec structs by @queue_consumer |
| Bot → Genji API | get_tournament_category / get_map calls; responses are trusted typed structs |
| Bot → Discord guild | Role add/remove + channel.send; bot acts with its own permissions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-04 | Tampering | event payload fields used in embed | mitigate | All inbound data is msgspec-decoded into typed structs (strong typing = validation); standings `name` is never used in a mention — only numeric `<@user_id>` |
| T-09-05 | Spoofing | winner ping / mention injection | mitigate | Mentions use numeric user id; `allowed_mentions=AllowedMentions(users=[winner], everyone=False, roles=False)` blocks @everyone/role-mention injection through any text field |
| T-09-06 | Elevation of Privilege | champion role grant | mitigate | `champion_role_id` comes from the trusted admin-configured category record (API), never from the event/user; bot never grants an arbitrary role. Bot's top role must sit above the champion role for add/remove to succeed (operator config) |
| T-09-07 | Denial of Service | duplicate announcements on retry | mitigate | @queue_consumer(idempotent=True) cycle-scoped dedupe on message_id; role transfer ordered before the single channel.send (Pitfall 5) to minimize the duplicate-post window |
| T-09-08 | Denial of Service | role-op rate-limit burst on simultaneous transitions | mitigate | `_ROLE_OP_DELAY` stagger between member edits; discord.py auto-handles 429s as the safety net |
| T-09-09 | Information Disclosure | error logs on fetch failure | accept | Failed get_map/get_tournament_category raises APIHTTPError/ValueError → DLQ (no secrets logged); a malformed event fails loud rather than posting a broken embed |
| T-09-SC | Tampering | npm/pip/cargo installs | accept | No package installs (RESEARCH: zero new dependencies; all primitives already in uv.lock) |
</threat_model>
