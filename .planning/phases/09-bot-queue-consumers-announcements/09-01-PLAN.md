<objective>
Wire the bot-side configuration and HTTP-client support that the tournament announcement handler (Plan 09-02) will consume, and lay down the Wave 0 test scaffolding for the whole phase.

Purpose: D-01 requires a dedicated `channels.tournament.announcements` config key (repointable knob), and D-08 requires a thin `APIService.get_tournament_category` wrapper so the handler can source the category name + champion_role_id on event receipt (D-07). Because `config.py` structs subclass `Base(msgspec.Struct, forbid_unknown_fields=True)`, the struct field AND both TOML blocks MUST land together or the bot fails at startup. This plan has no dependency on the handler, so it runs first and unblocks Plan 09-02.

Output: `Tournament(Base)` config struct + `Channels.tournament` field, `[channels.tournament]` blocks in both TOMLs (initialized to the existing announcements channel id per environment), `get_tournament_category` APIService wrapper, and the `apps/api/tests/bot/` test package (init, conftest fakes, config decode test, plus failing handler test stubs the next plan fills in).
</objective>
