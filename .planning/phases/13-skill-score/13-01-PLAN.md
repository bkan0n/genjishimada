    1. `CREATE SCHEMA IF NOT EXISTS skill;`

    2. `CREATE TABLE IF NOT EXISTS skill.snapshot` (lean, D-07 — only players with ≥1 eligible run get a row):
       - `user_id bigint PRIMARY KEY` (no FK needed; lean cache table)
       - `skill_score double precision NOT NULL`
       - `maps_cleared integer NOT NULL`
       - `video_clears integer NOT NULL`
       - `hardest_raw double precision NOT NULL`
       - `breakdown jsonb NOT NULL DEFAULT '[]'::jsonb` (per-map array, D-06; read via the existing jsonb↔msgspec codec)
       - `computed_at timestamptz NOT NULL DEFAULT now()`

    3. `CREATE TABLE IF NOT EXISTS skill.weight_config` (single typed-column row, D-09 — one column per weight, NOT key/value):
       - `id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY`
       - `diff_base double precision NOT NULL`
       - `gamma double precision NOT NULL`
       - `time_bonus double precision NOT NULL`
       - `shrink_k double precision NOT NULL`
       - `wr_bonus double precision NOT NULL`
       - `partial_factor double precision NOT NULL`
       - `medal_gold double precision NOT NULL`
       - `medal_silver double precision NOT NULL`
       - `medal_bronze double precision NOT NULL`
       - Add a `CHECK (gamma >= 0.5)` constraint (SPEC Constraint: `gamma ≥ 0.5` always; gamma=0 must never be representable as a shipped weight).

    4. Seed the single config row with the adopted defaults (D-09) ONLY if the table is empty — use `INSERT INTO skill.weight_config (diff_base, gamma, time_bonus, shrink_k, wr_bonus, partial_factor, medal_gold, medal_silver, medal_bronze) SELECT 1.44, 0.68, 0.55, 10.0, 0.10, 0.60, 1.12, 1.07, 1.03 WHERE NOT EXISTS (SELECT 1 FROM skill.weight_config);` so re-running the migration does not insert a second row.

    Do NOT add any pg_cron block. Per the PATTERNS caveat (lines 99-105) and CONTEXT D-03, the scorer lives in Python (`SkillService`), so a SQL cron cannot reuse the one rebuild routine; the nightly backstop is an app-side lifespan task added in plan 13-05. Omitting cron also keeps "applies cleanly on a fresh test DB" trivially true.

    Do NOT touch `lootbox.xp`, the Ninja→God `skill_rank` label, or any completion-count tier (SPEC Constraint: skill score is fully separate).
