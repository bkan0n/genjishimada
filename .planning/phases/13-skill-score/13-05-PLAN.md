<objective>
Wire the skill HTTP surface and the recompute machinery (SPEC req 4/5/7/8; D-01,
D-03, D-04, D-06, D-10): the four `/api/v3/skill/*` endpoints, the in-process
`skill.recompute.requested` listener that runs the single full rebuild (D-04), and
the app-side nightly lifespan task that is the durability backstop.

Purpose: This plan turns the service into a reachable API and stands up the fast-path
(event) + floor (nightly) recompute. Both the event listener and the nightly poller
call the ONE `recompute_all` routine (D-04). The nightly backstop is an APP-SIDE
lifespan task (mirroring `tournament_outbox_poller`), NOT pg_cron — the scorer lives
in Python, so a SQL cron cannot reuse the one rebuild routine (resolves the PATTERNS
planner flag).

Output: `routes/v3/skill.py` (new), `events/skill.py` (new), one event struct in
`events/schemas.py`, and a `skill_nightly_rebuild_poller` lifespan in `app.py`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → PATCH /skill/config | The config-write surface: untrusted caller + untrusted weight values; authz + validation gate here |
| client → GET /skill/* | Public reads; no write surface |
| event emit → recompute listener | In-process; the burst-of-events DoS vector is mitigated in the service (D-05) |
| nightly lifespan task → DB | Trusted internal scheduler; no external input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-13-12 | Tampering | weight values driving a recompute via PATCH | mitigate | msgspec typing rejects non-float; gamma ≥ 0.5 enforced in update_weights (plan 13-04) + DB CHECK (plan 13-01); PATCH only mutates the single audited config row |
| T-13-13 | Denial of Service | PATCH-triggered recompute or event burst | mitigate | D-05 in-flight collapse guard (plan 13-04) bounds concurrent rebuilds; a full rebuild is ~90ms; the nightly task overlaps safely under the same guard |
| T-13-14 | Information Disclosure | GET /skill/* responses | accept | Skill data is public leaderboard data; only public user_id exposed |
