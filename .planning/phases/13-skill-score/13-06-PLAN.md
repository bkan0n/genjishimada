<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| verify/reject/flag route → completions_service → emit | A verification change crosses into the recompute trigger; a burst (admin clearing the queue) is the DoS vector |
| client → GET /community/leaderboard?sort=skill_score | Untrusted `sort` param; the Literal allow-list is the injection gate |
| client → PATCH /skill/config | Covered by plan 13-05; exercised by this plan's authz test |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-15 | Denial of Service | recompute emit burst from verify/flag paths | mitigate | Emit is fire-and-forget post-commit; the listener's recompute is bounded by the D-05 in-flight collapse guard (plan 13-04) — N verify events coalesce to one rebuild |
| T-13-16 | Tampering | leaderboard `sort` parameter | mitigate | `sort_column` is a closed Literal allow-list (incl. the new skill_score); `sort_values` maps to a known column/CASE, never raw interpolation of caller input — no SQL injection |
| T-13-17 | Repudiation | un-verify / un-flag silently failing to recompute | mitigate | All four state-change paths emit; the integration test (Task 3) proves symmetric add/remove, so a missing emit path is caught in CI, not in production |
| T-13-18 | Spoofing | suspicious-flagged user retaining a score | mitigate | flag path emits → recompute drops the suspicious user (input query filters them) → score 0; asserted by the integration test |
| T-13-SC | Tampering | npm/pip/cargo installs | mitigate | No new package installs; nothing to verify |
</threat_model>
