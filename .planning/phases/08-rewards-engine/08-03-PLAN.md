<objective>
Wire the reward service (08-02) into the two existing hook points and prove the
end-to-end behavior with real-DB integration tests. Participation XP attaches to
submit_completion's first-completion branch (inside its open transaction); placement +
streak rewards attach to publish_pending_transitions when it processes a cycle_completed
row (inside the outbox transaction), riding the Phase-7 ~10s poller. This plan also adds
the non-participant streak reset sweep that the per-event reward service could not own,
and covers RWD-04 (streak increment/reset) plus the double-grant ledger guard end-to-end.

Purpose: Hooking into the existing submit transaction and outbox transaction keeps every
reward atomic with the work that triggers it and replay-safe via the 08-01 ledger — no
second scheduler, no API-side RabbitMQ consumer (the API has none; that would be net-new).

Output: two in-place hooks, the reset sweep (using fetch_all_streak_user_ids from 08-01),
the controller DI wiring update, and integration tests covering RWD-04 + idempotency.
</objective>
