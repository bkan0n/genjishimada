<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /api/v3/content/maps | Untrusted admin-supplied multipart (name + banner file) crosses into the API |
| auth/scope guard → handler | The `content:admin` scope gate that authorizes the write |
| relaxed input boundary | `name: str` (the Literal enum is gone) — value validation now lives in the service, not msgspec |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-10 | Elevation of privilege (authz bypass) | POST /content/maps | mitigate | `opt={"required_scopes": {"content:admin"}}` enforced by the global `scope_guard`; superusers bypass (test token is superuser, A4). Task 1 acceptance asserts the scope opt is present. A missing scope -> 403. |
| T-15-11 | Tampering / DoS (malicious/oversized upload) | banner UploadFile | mitigate | `request_max_body_size=1024*1024*25` (25 MB) caps the body (mirrors upload_image). Content-type is passed to S3 but the stored key extension is hardcoded `.png` (no content-type spoofing into an executable object key). Banner bytes are never executed/parsed server-side. |
| T-15-12 | Tampering (injection via map name) | name → SQL / object key / banner path | mitigate | SQL uses `$1` positional params (plan 15-03); the object key is `_strip_key`-reduced to `[a-zA-Z0-9]` (no path traversal); the empty-name + stripped-key collision guards (plan 15-03, REQ-05/06) run before any write. |
| T-15-13 | Spoofing (runtime-validation bypass) | relaxed `name: str` boundary | mitigate | msgspec still enforces field presence/type (missing/non-string name -> 400; Pitfall 3). Value validation is the service collision/empty guards + the `core.maps.map_name` FK backstop (plan 15-02). The Literal removal does NOT remove presence/type checks. |
| T-15-14 | Information disclosure | GET /utilities/map-names | accept | Returns only public map names (already exposed via autocomplete). No PII, low-value; inherits global auth unless excluded. No new sensitive surface. |
| T-15-SC | Tampering (supply chain) | npm/pip/cargo installs | mitigate | No new packages this phase (RESEARCH Package Legitimacy Audit: zero installs). No slopcheck checkpoint needed. |
</threat_model>
