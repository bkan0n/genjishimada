Build the data + storage layer for adding maps: `ImageStorageService.upload_map_banner` keyed by the stripped name (D-05/REQ-07), the new `MapContentRepository` (`insert_map_name` ON CONFLICT + `fetch_all_map_names`), and the new `MapContentService` with `create_map` (empty-name guard REQ-05, stripped-key collision guard REQ-06, banner upload, idempotent insert) plus `validate_map_name` (REQ-02, the consumer-side "did you mean"). <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin-supplied map name → SQL / object key / derived banner path | Free-form `name` string flows into a parameterized INSERT, the S3 object key, and the get_map_banner-derived read path |
| admin-supplied banner bytes → S3 object | Uploaded file content + content-type stored in object storage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-06 | Injection (SQLi) | insert_map_name / fetch_all_map_names | mitigate | All queries use `$1` positional asyncpg params — the name is never string-interpolated into SQL. Verified by source review + the create happy-path test inserting an arbitrary name. |
| T-15-07 | Tampering (object-key) | upload_map_banner key derivation | mitigate | The key is reduced to `[a-zA-Z0-9]` then lowercased (`_strip_key`), so no path traversal / arbitrary-prefix is possible from the name; extension is hardcoded `.png`. The collision guard (D-07) prevents one map's banner overwriting another's via a colliding stripped key. |
| T-15-08 | Tampering / DoS (file upload) | banner content + content-type | mitigate | Content-type is passed through to the S3 `ContentType` ExtraArg but the stored extension is always `.png` (no content-type spoofing into an executable key). The 25 MB body cap is enforced at the route boundary in plan 15-04 (`request_max_body_size`), bounding upload size. |
| T-15-09 | Spoofing (validation bypass) | post-Literal runtime gate | mitigate | `validate_map_name` (consumer) + the collision/empty guards (create) are the runtime replacement for the removed Literal enum (T-15-01 from plan 15-01); the `core.maps.map_name` FK (plan 15-02) backstops direct writes. |
</threat_model>
