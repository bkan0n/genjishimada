# Quick Task 260612-u82: PATCH /api/v3/skill/tiers Summary

Adds an admin-only `PATCH /api/v3/skill/tiers` endpoint that retunes the skill tier `percentiles` array and re-derives the tier boundaries from the current snapshot — symmetric with the existing `PATCH /skill/config` (weights), gated by the same `skill:admin` sentinel, with no change to scoring weights, the `skill_rank` CASE, the scorer math, or the `compute_tier_boundaries` SQL.

## What was built

- **SDK** (`libs/sdk/src/genjishimada_sdk/skill.py`): `SkillTiersUpdateRequest(Struct)` with `percentiles: list[float]`, added to `__all__` keeping the tuple alphabetically sorted (RUF022). Validation rules are documented as server-side, not msgspec-enforced.
- **Repository** (`apps/api/repository/skill_repository.py`): `SkillRepository.update_percentiles(percentiles, *, conn=None) -> dict` — `UPDATE skill.tier_config SET percentiles = $1 RETURNING boundaries, percentiles, computed_at`, binding the `float8[]` positionally (no string interpolation). `compute_tier_boundaries`, `update_weights`, `fetch_tier_config`, and the boundary SQL are untouched.
- **Exception** (`apps/api/services/exceptions/skill.py`): `InvalidPercentilesError(SkillError)` mirroring `InvalidGammaError`, carrying a specific reason string.
- **Service** (`apps/api/services/skill_service.py`): `SkillService.update_tier_config(percentiles) -> SkillTiersResponse`. Validates count==6, every value strictly in `(0,1)`, strictly increasing (raising `InvalidPercentilesError` on the first failing rule, before any write); then on one `self._pool.acquire()` transaction connection calls `update_percentiles` -> `compute_tier_boundaries` (the existing routine, NOT `recompute_all`) -> `fetch_tier_config`, returning the converted `SkillTiersResponse`. Added `_TIER_PERCENTILE_COUNT = 6` constant.
- **Route** (`apps/api/routes/v3/skill.py`): `update_tiers` handler `@patch(path="/tiers", opt={"required_scopes": {"skill:admin"}})`, `data: SkillTiersUpdateRequest -> SkillTiersResponse`; catches `InvalidPercentilesError -> HTTPException(HTTP_400_BAD_REQUEST)`. Same `skill:admin` string as `update_config`.
- **Tests**: 3 unit rejection tests (wrong length / out-of-range / non-increasing — each asserts `update_percentiles` and `compute_tier_boundaries` NOT awaited) + a request round-trip sanity test; integration `TestTiersPatch` (401 unauth, 401/403 non-superuser, superuser persist+re-derive with monotone/changed boundaries and restore of the seeded defaults, invalid -> 400 nothing persisted).

- **Found during:** Task 2 (`just lint-api`)
- **Issue:** `zip(percentiles, percentiles[1:])` for the strictly-increasing check tripped RUF007 (prefer `itertools.pairwise`).
- **Fix:** Imported `from itertools import pairwise` and used `pairwise(percentiles)`.

Left the struct import out of the service; it is imported where actually used (the route and the unit tests). No behavioral impact.
