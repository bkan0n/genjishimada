# Quick 260602-d96: Fix tournament end-announcements (poller `started` + bot dedupe) Summary

Restored correct, non-crashing boundary announcements: the poller now rides the new tournament's cycle info on the rollover card (Bug #1), the bot frames the title by the real transition and references the prior edition on deferred results, and both bot handlers dedupe winner mentions so a multi-category winner no longer triggers Discord `400 50035` → DLQ (Bug #2).

## What changed

### Task 1 — API: populate rollover `started` (commit `b605b2f`)
- **Repository** (`tournaments_repository.py`): added `fetch_active_edition_started_cycles()` — one JOIN `tournaments.cycles → tournaments.editions → core.maps` filtered `WHERE ed.status='active' AND cy.status='active'`, ordered by `cy.id`. Selects `cycle_id, category_id, map_id, map_code, map_name` plus `ed.started_at, ed.ends_at` (timing sourced from the EDITION — the cycle row has no `ends_at` column). Returns `[]` when no active edition exists (paused/hiatus).
- **Service** (`tournament_outbox_service.py`): in `process_awaiting_results_editions`, builds the `started` list once per edition (`fetch_active_edition_started_cycles` → `TournamentCycleStartedEvent`s) BEFORE the branches, and passes it as `started=` in BOTH the start-only branch (was `started=[]`) and the combined branch (was `started=[]`). Added the missing `TournamentCycleStartedEvent` import. Mark-first ordering, grant loop, idempotency key, results computation, `results_pending`, and `complete_edition` are all unchanged. No SQL inlined in the service (three-layer respected).

### Task 2 — Bot fixes (commit `fc995b3`)
- **Winner dedupe (Bug #2)** in BOTH `_on_edition_rollover` and `_on_edition_results`: `deduped_winners = list(dict.fromkeys(winners))`, used for BOTH the "Congratulations …" ping text AND `discord.AllowedMentions(users=…)`. Prevents the duplicate-snowflake `400 50035` DLQ crash on multi-category wins. Numeric-id-only mention rule and the CV2 ping-in-TextDisplay constraint preserved.
- **Title framing (Bug #1)** in `_on_edition_rollover`: replaced the hardcoded "A new rotation has arrived!" with a title computed from the now-populated fields — ended+started, started-only, or ended-only (hiatus). Kept the 🏆 emoji + gold accent; the conditional Results / Results-pending / New-Cycle sections are unchanged.
- **Deferred-results edition reference (item D)** in `_on_edition_results`: the deferred results card intro now references `event.edition_id` ("…for tournament #{id}…") so the drained-results announcement clearly ties to the prior edition. Still a SEPARATE new card (D-04) — no edit-in-place, no stored message id.

### Task 3 — Tests (commit `a4d00bb`)
Added to `tests/repository/tournaments/test_outbox_poller.py` (the harness with the edition/cycle factory fixtures):
- `TestPollerStartedPopulatedCombined` — no pending → combined rollover has `results` AND `started` populated (len == active child cycle count; `map_code`/`map_name`/`started_at`/`ends_at` present) [criterion a].
- `TestPollerStartedPopulatedStartOnly` — pending > 0 → start-only rollover with `results=[]`, `started` populated, `results_pending=True` [criterion b].
- `TestPollerStartedEmptyWhenPaused` — no active edition → `started=[]`, ended-only card, no crash [criterion c].
- `TestWinnerDedupeTransform` — guards the exact `list(dict.fromkeys(...))` transform the bot handlers now use (order-preserving, duplicate-free, idempotent). No bot pytest harness exists, so this covers the pure transform directly.
- Added `_retire_other_active_editions` helper: `fetch_active_edition_started_cycles` is a GLOBAL query, so the session-shared DB leaks sibling tests' active editions into `started`; retiring them first makes the count deterministic (the documented shared-test-DB contamination pattern).
