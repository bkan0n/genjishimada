<objective>
Fix two user-reported tournament-announcement bugs plus the API gap underneath bug #1.

- **Bug #1 (no "end" announcement):** the poller emits boundary rollover events with `started=[]` in both branches, so the new tournament's cycle info never rides the boundary card; the bot then renders a hardcoded "A new rotation has arrived!" title. Fix: populate `started` from the newly-created **active** edition's child cycles, and make the bot title reflect the real transition.
- **Bug #2 (results-card crash):** when one user wins multiple categories, the bot builds a duplicate winner-id list and passes it to `discord.AllowedMentions(users=...)`, which Discord rejects with `400 50035` → DLQ → results never post. Fix: order-preservingly dedupe winner ids in BOTH `_on_edition_rollover` and `_on_edition_results`.

Purpose: Restore correct, non-crashing boundary announcements that show the new tournament + results (or a results-pending message), with deferred results posting separately and referencing the prior edition.

Output: A new repo method, populated `started` in the poller (both branches), accurate bot framing, deduped winner mentions in both handlers, and regression tests on both sides.
</objective>
