# Quick Task 260814-e27: Add archived-state tribool filter to personal records search - Context

**Gathered:** 2026-08-14
**Status:** Ready for planning

<domain>
## Task Boundary

A community user requested the ability to filter their personal records (completions)
by whether the underlying map is archived. Add a tribool filter — `all` / `archived` /
`not_archived` — to the personal-records search path.

The affected chain (verified by scouting before planning):

- `apps/api/repository/completions_repository.py` → `fetch_user_completions()` (line ~33).
  Its `target_map` CTE is `SELECT ... FROM core.maps WHERE code IS NOT NULL` — there is
  currently **no** archived predicate, so archived maps are returned today.
- `apps/api/repository/completions_repository.py` → the world-records query backing
  `get_world_records_per_user` (same file; locate by grep).
- `apps/api/services/completions_service.py` → `get_completions_for_user()` (line ~295)
  and `get_world_records_per_user()`.
- `apps/api/routes/v3/completions.py` → `GET /completions` handler
  `get_completions_for_user()` (line ~87) and `GET /completions/world-records`
  handler `get_world_records_per_user()` (line ~105).
- `libs/sdk/src/genjishimada_sdk/completions.py` → shared type for the filter literal.
- `apps/bot/extensions/api_service.py` → `get_completions_for_user` (Route at ~line 1261)
  and `get_world_records_for_user` (Route at ~line 1294).
- `apps/bot/extensions/completions.py` → `/user-completions` command (line ~1170) and
  `/world-records` command (line ~1207).

`core.maps.archived` is a NOT-NULL-ish boolean column already used elsewhere
(`maps_repository.py` lines 806-821, 969, 1651). Existing code reads it both as
`archived = FALSE` and `archived IS NOT TRUE`.

</domain>

<decisions>
## Implementation Decisions

### Parameter shape (LOCKED)
- The filter is an explicit string enum, not a nullable bool:
  `Literal["all", "archived", "not_archived"]`.
- Name the query parameter `archived`.
- Define the literal alias once in the SDK (`libs/sdk/src/genjishimada_sdk/completions.py`,
  e.g. `ArchivedFilter = Literal["all", "archived", "not_archived"]`), export it from the
  SDK, and import it in the API route, the service, and the bot — do not redeclare the
  literal in more than one place.
- Rationale: self-documenting in the OpenAPI schema and it renders as a clean choice
  list on the Discord slash command.

### Default behavior (LOCKED)
- Default is `"all"` — identical to today's behavior.
- This is a strict non-breaking addition: any existing caller that omits `archived`
  MUST get byte-identical results to before this change. Do NOT change the default to
  `not_archived` "for cleanliness."

### Scope (LOCKED)
Full vertical slice across three surfaces, for **both** personal-records endpoints:
1. `GET /api/v3/completions` (personal records / `/user-completions`)
2. `GET /api/v3/completions/world-records` (`/world-records`)

Each of those needs: repository query predicate → service passthrough → route parameter
→ SDK type → bot `api_service` param → bot slash-command option.

### SQL semantics (Claude's Discretion, with guidance)
- `all` → no archived predicate added at all (preserves the current query plan and results).
- `archived` → only maps where archived is true.
- `not_archived` → only maps where archived is not true.
- Prefer adding the predicate to the `target_map` CTE (`core.maps`) rather than filtering
  after the join, so pagination counts and window-function ranks stay consistent with the
  filtered set.
- Use asyncpg positional params (`$N`) — never string-interpolate the filter value into SQL.
  A common safe pattern here is a single parameter plus a three-way SQL predicate, e.g.
  `AND ($N = 'all' OR (archived IS TRUE) = ($N = 'archived'))`, but the planner may choose
  a clearer construction so long as it is parameterized.

### Ranking caveat to think through (Claude's Discretion)
- `fetch_user_completions` computes `rank() OVER (PARTITION BY map_id ORDER BY time)`.
  Filtering maps changes which maps appear, but must NOT change a record's rank on the maps
  that do appear. Verify the predicate placement does not corrupt displayed ranks — the
  filter selects which maps are listed, not which competitors count toward a rank.

### Bot command UX (Claude's Discretion)
- Expose as an optional slash-command option. Omitted → `all`, matching the API default.
- Use `app_commands.Choice` / a `Literal` so Discord shows the three options with
  readable labels (e.g. "All", "Archived only", "Not archived").

</decisions>
