<objective>
Add the skill-score column (recently added to the community leaderboard) to the
"get rank card data" endpoint so the rank card mirrors exactly what the leaderboard
exposes per player.

The leaderboard (`community_repository.fetch_community_leaderboard` →
`CommunityLeaderboardResponse`) exposes FOUR skill fields per row:
- `skill_score: float` — numeric skill score, COALESCE'd to 0 (D-07/D-08)
- `skill_tier: int` — percentile tier 1..8, 0 = Unranked (`width_bucket(skill_score, boundaries)+1`)
- `skill_percentile: float` — 0..1 population percentile of skill_score
- `skill_tier_name: str` — display name (Unranked..Champion) mapped from `skill_tier`
  via the SDK single-source-of-truth `genjishimada_sdk.skill.skill_tier_name`

This plan adds those same four fields to `RankCardResponse` for a single user.

Purpose: The frontend rank card should surface a player's skill standing with the
same shape the leaderboard already uses, so the website can reuse its rendering.
Output: `RankCardResponse` gains four skill fields; a new single-user repository
query supplies them; the rank card service wires + name-maps them; integration tests
cover both the snapshot-present and zero-eligible (Unranked) cases.
</objective>

Extracted from the codebase — use these directly, no exploration needed.

Leaderboard skill exposure (the contract to mirror), from
apps/api/repository/community_repository.py fetch_community_leaderboard SELECT —
the three computed skill columns plus their joins:

- coalesce(ss.skill_score, 0) AS skill_score
- CASE WHEN coalesce(ss.skill_score, 0) <= 0 OR cardinality(tc.boundaries) = 0 THEN 0
       ELSE width_bucket(ss.skill_score, tc.boundaries) + 1 END AS skill_tier
- coalesce(
      (SELECT count(*) FROM skill.snapshot s2
         WHERE s2.skill_score > 0 AND s2.skill_score <= ss.skill_score)::float8
      / NULLIF((SELECT count(*) FROM skill.snapshot s3 WHERE s3.skill_score > 0), 0),
      0.0) AS skill_percentile
- LEFT JOIN skill.snapshot ss ON u.id = ss.user_id
- LEFT JOIN skill.tier_config tc ON TRUE

SDK tier-name helper (single source of truth), from libs/sdk/.../skill.py —
skill_tier_name(tier): 0 -> "Unranked"; 1..8 -> Bronze..Champion; out-of-range -> "Unranked"
(implemented as SKILL_TIER_NAMES.get(tier, "Unranked")).

How the leaderboard service name-maps each row, from
apps/api/services/community_service.py get_community_leaderboard — imports
skill_tier_name from genjishimada_sdk.skill, then for each row sets
row["skill_tier_name"] = skill_tier_name(int(row["skill_tier"])) before msgspec.convert.

RankCardResponse current shape (struct), from libs/sdk/.../rank_card.py — fields
rank_name, nickname, background, total_maps_created, total_playtests, world_records,
difficulties, avatar_skin, avatar_pose, badges, xp, community_rank, prestige_level,
then defaulted computed fields background_url="", rank_url="", avatar_url="" set in
__post_init__. New non-defaulted fields must be added BEFORE the defaulted ones.

Skill table column names (confirmed from migrations 0027/0028):
- skill.snapshot(user_id bigint PRIMARY KEY, skill_score double precision NOT NULL, ...)
- skill.tier_config(boundaries float8[] NOT NULL DEFAULT '{}', percentiles ..., computed_at)

Rank card service assembly point, from apps/api/services/rank_card_service.py
get_rank_card_data: all reads happen inside `async with self._pool.acquire() as conn:`
and the repo methods take `conn=conn`. The final `return RankCardResponse(...)` is where
new fields are passed.
