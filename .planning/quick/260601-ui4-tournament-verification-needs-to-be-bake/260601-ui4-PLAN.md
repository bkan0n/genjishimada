<objective>
Fix the tournament verification hang: verifying a PB tournament completion while its
cycle is `finalizing` never persists the verdict, so the edition drain gate
(`count_inflight_verifications`) never clears and the edition rollover hangs in
`awaiting_results` forever.

Root cause: `_propagate_tournament_verification` gates on
`_resolve_active_cycle` → `get_active_cycle_by_map_id`, which filters
`status = 'active'` and therefore excludes `finalizing`. During rollover the child
cycle is `finalizing`, so the lookup returns None, propagation no-ops, and the
`tournaments.completions` row stays `pending`. The drain gate counts `pending` rows
on cycles `IN ('active','finalizing')`, so the count stays > 0 forever.

Fix (mirrors `TournamentService._set_verified`): resolve the cycle from the
tournament completion's OWN `cycle_id` (status-agnostic), not the active-only map
lookup. Scope strictly to the verify/propagation path — leave the submit-time
`get_active_cycle_by_map_id` call (completions_service.py:665) untouched, where
active-only is correct (new runs must not join a finalizing cycle).

Purpose: Unblock edition rollover when verifications land during the finalizing window.
Output: One-method fix in completions_service.py + a real-DB regression test + an
updated unit test for the new resolution path.
</objective>
